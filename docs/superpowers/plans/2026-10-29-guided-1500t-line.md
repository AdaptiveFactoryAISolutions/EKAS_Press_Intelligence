# Guided 1,500-ton Line Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task. Checkboxes track actual completion.

**Goal:** Deliver the approved connected ten-station line with a beginner configuration wizard, persistent validated setups and public EKAS evidence.

**Architecture:** Add a distinct native `stamping_line` plant through the existing immutable runtime-overlay mechanism. A typed application configuration resolves to a native ScenarioConfig; durable native jobs remain the only execution path. A separate beginner wizard consumes server field metadata and versioned drafts; existing expert workflows stay available.

**Tech Stack:** Python3.12, Pydantic2, FastAPI, SQLite, native HistorianSim, browser ES modules/CSS, locally bundled Fluent components if compatible, Playwright.

**Spec:** ../specs/2026-10-29-guided-1500t-line-design.md (approved by user).

## Global constraints

- Maximum 10 SPM =600 strokes/hour; ten continuous-strip stations, one finished part per stroke after die fill by default.
- Full reel→loop→straightener→feeder→die→washer→manual packing plus independent scrap removal.
- Preserve vendor pins, existing runtime/reference service, source verification, private truth and adverse evidence.
- No JSON/secrets in beginner setup; one screen per step, Back/Next/Save, accessible supplemental Fluent help.
- No qualification assertion from configuration preflight; explicit force units, practice scope and source/configuration versions.
- No paid provider invocation, production activation or merge required for this implementation.

## Review focus

1. A user enters600 as SPM: reject server-side, correct field identified (Task1/3).
2. A stale tab overwrites a draft or duplicate Run creates two jobs: revision conflict/idempotent submission (Task3).
3. Cold washer or slow packer silently loses parts: finite queues/conservation and causal stop propagation (Task2).
4. UI assumes qualified data or replaces failed adapter calls with fiction: explicit statuses/no fallback (Task4/5).
5. Force-unit changes relabel rather than convert and die stations multiply output: SI force boundary/exact counters (Task1/2).
